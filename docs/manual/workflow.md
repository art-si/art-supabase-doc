# 审批工作流

审批中心承载待办、已处理、我发起、流程定义、版本管理、审批监控和失败补偿。核心原则是：已发布版本保持不可变，每个业务实例保留当时的流程快照。

![审批工作台](/screenshots/workflow-workbench.png)

## 审批工作台

- **待我审批**：当前用户需要处理的任务。
- **我已处理**：已经审批、驳回或转交的任务。
- **我发起的**：查看业务申请及流程进度。
- **委托/转交**：在授权和有效期内转移处理责任。

处理前核对业务单据、申请人、金额或关键字段、当前节点、历史意见和附件。审批、驳回、撤回、转交、委托和催办是不同权限，不应合并成一个宽泛操作。

## 流程定义

推荐配置顺序：

1. 新建草稿并选择业务场景。
2. 配置发起、审批、条件、会签/或签和结束节点。
3. 为条件字段设置稳定的数据契约。
4. 校验流程，使用测试业务数据走完整路径。
5. 发布新版本；已有实例继续使用原版本。

![流程版本治理](/screenshots/workflow-governance.png)

## 回调与补偿

审批结束后的业务状态更新通过回调或 Outbox 执行。若回调失败：

1. 在审批监控查看失败节点、次数和最后错误。
2. 判断是临时网络故障、数据状态冲突还是契约变化。
3. 对可恢复错误执行重试；不可恢复错误先修正数据或代码。
4. 人工补偿必须记录操作人、原因和结果。

## 安全边界

- 任务读取按租户和处理人范围控制。
- 审批动作同时校验任务状态、处理人、按钮权限和业务记录。
- 平台超级管理员不应替代业务审批人直接完成日常审批。
- 历史轨迹、意见和版本快照属于审计证据，不能被普通编辑覆盖。
