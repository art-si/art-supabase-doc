# 系统管理

系统管理承载平台级基础配置。管理员应先配置组织与权限，再逐步启用业务能力，避免同时修改大量控制面配置。

## 功能清单

| 功能           | 用途                     | 关键注意点                     |
| -------------- | ------------------------ | ------------------------------ |
| 用户管理       | 用户状态、组织、角色     | 停用与会话回收要配合           |
| 角色管理       | 页面和按钮授权           | 用普通账号验证最小权限         |
| 菜单管理       | 动态路由和操作权限       | 组件路径必须真实存在           |
| 租户管理       | 多租户控制面             | 仅平台超级管理员跨租户维护     |
| 组织管理       | 部门与人员归属           | 避免破坏在用层级               |
| 参数设置       | 运行时业务参数           | 变更前记录原值与影响范围       |
| 编号规则       | 单据编号策略             | 场景、租户、并发与唯一性要一致 |
| 网站配置       | 品牌、站点和发布         | 发布属于平台超级管理员控制面   |
| 字段权限       | 敏感字段可见范围         | 前端隐藏之外仍需服务端裁剪     |
| 消息提醒       | 通知规则和状态           | 关注失败重试与接收范围         |
| 电子围栏       | 地图围栏业务配置         | 地图 Key、坐标和租户范围       |
| AI 配置中心    | Provider、模型、能力配置 | 私密 Key 只存服务端            |
| AI Prompt 中心 | 提示词版本与启用         | 变更应保留版本和审计           |

## 编号规则

编号规则用于订单、运单、凭证、报销等单据。修改前确认场景代码、前缀、日期片段、流水长度和重置周期。业务保存应由统一编号服务分配，不能在页面内拼接，以免并发重复。

## 网站配置

网站配置可能影响所有用户的登录页、品牌信息或公开展示。建议使用“编辑 → 预览 → 发布”的流程；发布和跨租户配置必须保留平台超级管理员校验。

## AI 配置

管理员配置 Provider、模型、能力开关与租户覆盖关系。普通用户可以使用已启用的安全能力，但不能接触 Provider 密钥、全局配置或受控写入开关。

配置变更后应在 AI 运行中心检查成功率、延迟、Token 和失败原因，并准备回滚到上一版本。
