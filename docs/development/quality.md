# 测试与质量门禁

质量检查从改动文件开始，再逐步扩大到类型、单元、数据库、构建和真实浏览器。已有失败与本次新增失败要分开报告。

## 日常门禁

```powershell
pnpm icons:check
pnpm ui:audit
pnpm reuse:audit
pnpm dependencies:audit
pnpm permissions:audit
pnpm database:security:audit
pnpm typecheck
pnpm lint
pnpm test:unit
pnpm lint:stylelint
```

聚合命令（`check:fast` 不含 Stylelint，`check` 包含上述全部日常门禁）：

```powershell
pnpm check:fast
pnpm check
```

主项目 `pnpm lint` 同时检查平台源码、平台脚本与测试、业务模块源码、模块脚本、模块独立测试目录及模块 Vite 配置。业务模块页面和组件执行与平台相同的 API 访问边界规则：通过公开 API 入口访问后端，不直接导入 Supabase client 或具体 provider。模块自行运行的检查仍应保留，用于独立交付。

全量类型检查使用 `pnpm typecheck`：该命令为覆盖全部业务模块的检查配置了 8GB Node 堆上限。直接运行 `vue-tsc` 会使用 Node 默认上限，可能因内存不足退出。内存不足、人工停止或仍在运行都不算检查通过；资源紧张时应顺序执行类型检查、浏览器验证和构建。

`pnpm lint:stylelint` 同时覆盖平台及业务模块的 CSS、SCSS 和 Vue 文件。主项目类型检查不能代替模块自己的类型检查；跨模块修改必须逐一运行受影响模块的 `typecheck`。

跨模块交付还需执行各受影响模块自己的 `check`。`pnpm modules:check` 可以统一执行，但会自动初始化模块并在依赖不完整时修复安装；仅核验现有工作区时，可在各模块目录直接运行 `pnpm check`。各模块的检查范围以自己的 `package.json` 为准，不能把缺少单元测试的模块描述为已通过单元测试。

`pnpm dependencies:audit` 检查十个业务模块源码中的静态导入、再导出、字面量动态导入和 `import('包名').类型` 引用，包含 Vue 脚本与源码内测试。外部包须在模块自己的依赖声明中存在；路径别名按模块 TypeScript 配置识别。平台发布清单中的 `.mjs` 构建脚本，其相对静态导入和再导出依赖也须包含在发布清单中；修改打包边界后额外运行 `pnpm pack --dry-run --json` 核对实际文件列表。该门禁已纳入 `check:fast` 和 `check:ci`，不能代替冻结锁文件安装、依赖版本兼容性检查或模块构建；模板自动导入、运行时拼接的导入路径不在其覆盖范围内。

## 专项检查

组卷窗口完整读取题库后按每页 50 道显示，全量搜索不受展示分页限制，勾选状态保存在跨页集合中；课程关联试卷完整读取后使用共享 `ArtForm` 的 `selectV2`，避免为数千张试卷创建全部选项节点。`smis-learning-export.spec.ts` 验证第 5,001 道题和试卷可搜索、题目切换搜索后仍保持勾选，以及虚拟下拉展示节点少于 50 个。手机编辑表单使用单列，宽度检查针对完整控件外框，不能误用扣除字数提示后的原生输入区域。

题库、试卷、考试记录、课程和学习记录导出统一使用 `loadAllDocumentPages`，不再依赖一次请求前 5,000 行。`smis-question-export.spec.ts` 和 `smis-learning-export.spec.ts` 以 5,001 条合成数据检查 Excel 末行和缺页阻止下载，并检查正常导出的专注模式进入、可见退出按钮及 Esc 恢复。学习考核页面同时包含多个表格页签，专注模式验收定位当前可见表格并保留页签上下文。

共享 `ArtTableQuery` 的默认导出通过 `loadTableExportRows` 每批读取 500 行，复用完整分页与租户范围变化检查，保留筛选快照和自定义分页字段。超过导出上限、请求失败或已声明总数但缺页时不生成文件；无总数的响应按短页结束，不能将单页长度推断为全量总数。自定义响应适配器应返回真实总数。`table-infrastructure.test.ts` 覆盖分页、筛选快照、无总数、上限、缺页和失败；`art-table-export.spec.ts` 使用独立合成数据在桌面及手机检查 Excel 最后一行、缺页后重试和超限阻止下载。这些验收不证明线上 RLS 或业务 API 的权限正确性。

公共分页读取在每批请求前后检查租户范围，Excel 导出在保存文件前再次检查，租户切换后拒绝完成旧范围的操作并提示刷新重试。检查记录切换修订号，因此切到其他租户后再切回也会取消旧操作。普通用户的伪造租户 ID 不会变成跨租户授权；客户端检查不能代替 RPC/RLS 的真实身份与租户边界。单元测试覆盖平台全部、平台指定、普通用户和伪造普通范围，以及文件生成后的范围变化；培训导出浏览器用例暂停第一页响应后，通过桌面租户菜单切换，核对无后续导出页、无下载和可重试提示。手机布局没有这个租户菜单交互入口，该专项用例由桌面项目验证。

完整分页读取在开始时保存查询参数快照，包括嵌套的日期范围与数组，避免用户在导出过程中修改筛选导致后续页混入其他条件。区间分页与页码分页使用同一策略；不要逐页从可变表单状态重新取筛选。单元测试在第一页请求期间修改原始关键词和日期，并核对后续页仍使用初始条件。该快照只固定请求参数，不代表跨请求数据库事务快照；数据本身的并发变化仍需由业务和服务端处理。

业务模块独立运行时由 `createModuleViteConfig` 统一使用平台 `public` 目录，保证地区数据和设备附件示例在开发服务器及构建产物中具有相同路径。十个业务模块当前没有自己的公共资源目录；独立的网站模块使用自己的 Vite 配置和资源目录。`module-public-assets.test.ts` 运行实际最小构建，并逐字节核对输出 JSON、图片和 PDF；该测试不能代替各业务模块的完整生产构建。

导出筛选结果时，分页大小只是单次请求大小，不能当作完整数据上限。单据和明细列表复用 `loadAllDocumentPages` / `loadAllLinePages` 分页取齐；导出取数不得修改列表的可见行状态。初始库存导出从原始单据取数，再将每张单据的明细展开一次，避免按明细展示时重复展开同一单据。导出上限应在文件生成边界明确报错，不能静默丢弃后续页；按钮文案必须说明实际导出范围。浏览器验收应解析下载文件，核对超过一页的数据行数、首尾记录和重复记录，而不仅检查下载事件。

仓储导出浏览器用例集中在 `tests/e2e/wms-document-export.spec.ts`，供应链导出用例集中在 `tests/e2e/scm-document-export.spec.ts`；库存主数据页面用例保留在 `mdm-inventory-pages.spec.ts`。公共测试数据与初始化由 `tests/e2e/support/inventory-fixtures.ts` 提供，测试文件不得互相导入，以免重复注册用例。完整导出测试统一命名为 `*-export.spec.ts`，由 `test:e2e:exports` 自动发现，文档中心视图测试另外显式包含。新增导出用例不需要维护命令中的文件清单。测试清单检查只能确认用例被发现，不能代替实际执行和下载文件检查。

`ArtTableQuery` 的内管列表传入 `current/size`，使用 `from/to` 的查询接口必须在页面取数入口复用 `pageInfoHandler` 转换。按明细展示也使用转换后的范围分页，不能直接读取接口默认范围。验收同时核对列表每页行数、翻页结果与全量导出，避免列表一次渲染大量记录或换页仍显示首屏。BOM 导出必须保留列表的分类及指定记录筛选；ESOP 导出保留分类范围。

RPC 的包含式分页区间统一由 `src/utils/supabase/pagination.ts` 的 `buildSupabaseRpcRange` 构造。各业务接口保留自己的默认单次分页大小；完整导出通过重复分页读取，不以请求上限代替文件生成限制。共享函数拒绝非安全整数，起始偏移修正为零后再约束结束位置。复用审计拒绝在 API 中直接对 `p_from`、`p_to` 重复使用 `Math.max`；分页单元测试覆盖负数、倒序区间及非法数值。

全量分页读取 `fetchAllRangePages` 的分页大小必须是正安全整数，非法输入在发送查询前失败。结果累积逐条追加，避免大单页数据展开为函数参数时超出运行时参数数量限制；单元测试覆盖 20 万条单页数据的完整返回。

接口跨批合并全量读取结果时，先收集数组批次，再使用原生 `flat` 展平，保留原有顺序和错误处理。复用审计禁止在 API 中把查询结果的 `data` 直接展开为 `push` 参数，避免分页公共函数已安全、调用方仍发生参数溢出的情况。

单据与明细分页由 `document-detail-list.ts` 共用读取逻辑：有总数时验证结果是否完整，无总数时继续读取满页后的数据，直到不足一页。非法分页参数、无效总数和提前结束的已知结果必须失败，不能把部分数据当作完整列表；原始分页错误继续交给调用方处理。相关测试统一放在 `tests/unit`，由主仓默认单元测试命令执行。

存储兼容性恢复只能通过 `StorageConfig.clearVersionedStorage` 清理本应用版本化缓存，禁止使用 `localStorage.clear()` 清空整个来源的存储。记住账号、记住密码偏好、主题和其他应用存储必须保留；`storage-cleanup.test.ts` 验证这一边界。登录浏览器测试使用哈希导航保留部署目录前缀，验证默认填入及浏览器已保存凭据的恢复行为。

共享分页读取拒绝无效总数、缺失后续页，以及实际记录多于已声明总数的矛盾响应；不能把总数零值与非空记录组合当作完整第一页。提示统一使用“数据”表述，适用于单据、主数据和配置列表。单元测试覆盖低报总数，危废仓库浏览器用例验证这种响应不产生下载、按钮恢复且列表仍可使用。

```powershell
pnpm check:ci
```

它覆盖图标、UI、复用、模块依赖、权限和数据库静态安全审计、类型、ESLint、Stylelint、覆盖率、项目快照、生产构建、体积预算以及公开认证、关键业务和核心页面 E2E。真实数据库测试 `test:db` 不在该聚合命令内，需要按改动范围单独执行。

数据库静态审计只能证明仓库中的安全契约满足规则，不能代替真实身份下的租户隔离与权限验证。数据库策略断言同样应结合运行身份、测试数据和实际覆盖范围报告结果。

`test:coverage` 使用 Node 的实验性覆盖率，统计单元测试实际加载且匹配 `src/**/*.ts`、`supabase/functions/_shared/*.ts` 和 `scripts/*.ts` 的文件。当前要求行覆盖率至少 85%、分支至少 70%、函数至少 80%。该报告不包含未被加载的源码，也不覆盖 Vue 模板、业务模块全部源码或浏览器交互；不能据此宣称整个项目具有相同覆盖率。报告结果时应同时说明统计文件数、覆盖范围和未完成的浏览器验证。

使用 `VITE_OUT_DIR` 指定构建目录时，体积检查必须指向同一次构建的输出，例如 `pnpm exec tsx scripts/check-bundle-budget.ts .artifacts/production-build`。浏览器验收也应使用该构建，避免用旧产物证明新改动有效。

项目结构或规范修改后先运行 `pnpm snapshot:ai`，再运行 `pnpm snapshot:check`。生成成功不代表校验通过；并行任务修改源码时，快照可能随即过期，需要在交付前对最终工作区重新生成和校验。检查结果应记录对应命令、退出状态和验证范围。

## 前端视觉验收

源码使用的 Remix、Vaadin、Dashicons、Iconamoon、Fluent、Icon Park、IX 和 Solar 图标由 `pnpm icons:generate` 从锁定版本的图标库生成到 `src/assets/icons/collections.generated.json`，共享 `ArtSvgIcon` 自动注册，平台和独立模块共用。`configured-icons.json` 记录已核验的后台菜单图标名；新增后台图标时也应同步此清单。新增或替换图标后先生成，再运行 `pnpm icons:check`，不要手工修改生成文件。构建和 CI 会拒绝已支持图标库中的无效名称或过期的数据。当前检查覆盖源码字面量和配置清单；未记录的后台配置、其他图标库及动态拼接名称仍需单独核验。

图标验收需屏蔽外部 Iconify 服务，确认代表性图标仍显示且无外部图标请求，并检查尺寸、样式和无障碍属性。截图前核对图标已完整显示；不能把缺少图标的画面直接接受为基准。

图标选择器的目录与浏览器缓存都属于外部数据边界。解析集中在组件旁的 `icon-data.ts`，校验集合前缀、名称、分组和缓存期限；损坏、过期或混入其他图标库的缓存必须重新加载，不能用类型断言直接当作有效列表。`icon-picker-data.test.ts` 覆盖异常数据，`art-icon-picker-data.spec.ts` 使用真实组件验证缓存恢复、选择结果和请求失败回退。完整目录仍依赖外部服务，本地图标清单不代表整个图标库已离线。

目录请求失败时，从 Iconify 已注册数据中列出当前图标库的本地图标。不能将 Remix 图标名称改成其他前缀作为回退；没有本地图标的集合应显示失败与重试入口。存在本地图标时，明确显示回退状态并提供加载完整图标库的操作；网络恢复后可替换回退列表并清除该状态，无需刷新页面。跨图标库浏览器检查须屏蔽外部图标服务，逐项确认回退选项有实际 SVG，且选择结果属于当前集合。恢复检查还须覆盖请求失败后重试成功，以及桌面、移动端、深色和阴影模式的实际状态与布局。

跨技术边界的普通对象类型收窄由 `src/utils/type-guards.ts` 统一提供；Supabase 键名转换和图标解析直接复用。新增调用方不应再在业务页或供应商工具中复制相同校验。

无时区日期范围的时间边界由主仓库 `src/utils/time/date-boundary.ts` 统一提供。列表过滤和 RPC 参数复用 `toDateStartTimestamp`、`toDateEndTimestamp`，空值返回 `null`，结束边界保留现有的毫秒精度；不要复制按业务名称命名的同类函数。这两个函数不进行时区转换。明确携带 `+08:00`、UTC 或使用次日开头作为排他边界的查询须保留各自语义，不能直接替换。复用审计检查公共函数归属，日期测试验证空参数和日历日期不发生转换。

用户界面不能只看源码。至少验证：

- 成功、加载、空、失败/重试、无权限和禁用状态。
- 1440 桌面、1280 窄桌面，以及业务要求的移动宽度。
- 浅色/深色主题和受影响的边框/阴影模式。
- 长名称、大数值、中英混排、密集数据和 200% 缩放。
- 键盘焦点、弹窗焦点返回、控制台错误和水平溢出。

截图和报告使用脱敏测试数据，存入忽略的 `.artifacts`，不要提交租户、客户、财务、凭证或个人信息。

字典验收必须覆盖新标签页、刷新页面和租户切换后的缓存失效。测试登录复用 `fetchAllRangePages` 完整加载字典，不能用一次未分页查询预置截断的数据。`dictionary-bootstrap.spec.ts` 在清空测试缓存后检查中文工作量选项及超过 1000 项的完整加载，并纳入 `test:e2e:critical`。共享页头在租户初始化和范围变更后重新加载字典；失败显示可重试提示。并行开发导致页面热重载时，须使用关闭热更新的独立预览或当前生产构建复核，不能将请求被重载中断的结果判为通过。

独立开发预览若设置 `watch: null`，源码修改后必须重启该预览服务；关闭文件监听会保留已转换模块，刷新浏览器不能证明加载了最新源码。记录服务端口、启动时点和对应改动，避免使用其他任务的服务作为验收依据。

浏览器测试的页面哈希导航使用 `#/路径`，保留 Playwright `baseURL` 中的部署目录；ESLint 会拒绝 `page.goto('/#/路径')` 及对应模板写法。测试资源使用相对当前页面的 URL，避免把预览服务器兼容的网站根路径当作生产部署规范。

截图前等待业务内容就绪：页面根节点可见不代表加载完成。共享 `ArtAsyncState` 必须结束忙碌状态，骨架与加载遮罩消失，字典选项、字体和品牌图片完成加载，再检查需要展示的业务区域。工作台额外检查六个概览指标已出现，不能把骨架画面当作正常内容基准。

截图基准更新与回归验收分开执行。需要重新审阅全部当前画面时，使用 `--update-snapshots=all`；默认更新可能保留容差以内的旧图，不能据此判断当前渲染结果。检查文件更新时间并逐张审阅脱敏截图后，再执行不带更新参数的回归测试。截图中的固定测试日期不代表工作台当前日期。

## CAD 文件预览验收

CAD 预览包含独立 Worker 和 WASM，构建成功或出现画布都不能证明模型解析成功。验收时应：

- 使用真实 STEP/STP 模型，确认预览中出现几何模型和非零网格数量。
- 核对 OCCT Worker、运行脚本和 WASM 从当前部署前缀成功加载；WASM 响应必须使用 `application/wasm`。
- 检查页面运行异常、资源失败和模型加载提示，并实际操作适配、旋转或线框等控制。
- 按实际样本报告覆盖范围；简单立方体通过不能代表复杂装配、IGES、BREP 或所有浏览器均通过。

请假信息导出复用 `loadAllDocumentPages`，每批 500 条保留组织、申请人和日期筛选，不能用一次 5,000 条请求代替全量导出。`smis-leave-export.spec.ts` 在桌面和手机视口解析 5,001 条记录的实际 Excel，核对末条单号及申请人；缺页用例检查不生成文件且按钮恢复。隔离身份和接口模拟仅证明客户端取数与文件生成行为，不能代替线上 RPC 的租户和权限验证。

危险源台账导出同样复用完整分页加载，不能用一次 100,000 条请求推断结果完整。`smis-hazard-source-export.spec.ts` 模拟服务端单次最多返回 1,000 条，解析 1,001 条实际 Excel，核对末条记录、中文分级及责任人员工号；桌面和手机端同时检查指定场所筛选、缺页阻断和按钮恢复。专注模式验收保留场所导航，核对分页可见、按钮与 Esc 退出后的布局恢复。
