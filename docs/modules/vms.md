# VMS 车辆管理

VMS 围绕“一车一档”维护车辆档案、保险、年检、违章、事故、维修保养、例检、里程、零部件和到期提醒。

## 基础资料

正式录入车辆前，先维护保险公司、供应厂商、零部件类别和零部件。跨 HR/TMS 读取人员、司机或承运商时，系统通过租户隔离、字段最小化的安全 RPC 获取选项，VMS 不直接引用其他业务仓源码。

## 车辆入档

1. 在“车辆档案管理”新增车辆。
2. 填写车牌、车辆类型、品牌型号、识别代码、载重/容积、归属和状态。
3. 上传证照与必要附件。
4. 提交审核；审核通过后进入可用档案。
5. 在详情中继续维护保险、年检、维修、事故、例检和里程。

车牌和车辆识别信息应具有租户内唯一性。新增、编辑、提交、审核和删除分别受按钮权限和服务端规则控制。

## 一车一档

车辆详情聚合基本资料、司机、零部件、保险、年检、违章、事故、维修保养、例检、里程与设备信息，适合审查车辆当前状态和历史证据。

![车辆全生命周期档案](/screenshots/vehicle-lifecycle.png)

## 日常记录

- **保险**：保险公司、险种、保单、有效期与附件。
- **年检**：检验日期、有效期、结果与证明材料。
- **维修保养**：项目、里程、供应商、费用、计划和完成状态。
- **例检**：检查项、异常、整改和复核结果。
- **事故/违章**：时间、地点、责任、处理、费用与证据。
- **里程**：读数、来源和时间；异常回退或跳变应被识别。
- **零部件**：领用、安装、寿命、替换和供应商信息。

## 到期提醒与车辆健康

提醒中心覆盖保险、年检、保养、零部件和车辆寿命。建议按“即将到期 → 生成处理任务 → 完成业务记录 → 关闭风险”的顺序处理，而不是直接删除提醒。

AI 车辆健康基于当前档案给出风险解释和建议，不替代人工检查或法定检验。数据缺失时，应先补齐里程、维修或证照记录。

## 车务管理

- **自有车任务**：读取 TMS 主运输任务，按车辆档案的 `vehicle_ownership='self_operated'` 判断自有车。国产/进口字段不参与车辆归属判断。列表区分计划发车、实际发车和实际到达；实际事件尚未登记时显示“—”。正向货与返程货共用主任务，登记费用与财务已审核费用分别展示。
- **油卡与电卡**：分别建档、分别核算余额，支持明细和卡片视图。充值、消费和冲正保留流水轨迹；切换卡号或流水类型后，查询条件、列表和所选卡余额同步更新。运单燃油费用通过受控接口关联油卡消费，重复保存不重复扣款。
- **车辆配件**：使用库存台账与车辆领用记录，领用、归还、丢失和损坏按实际数量登记，只有实际归还数量回到库存。定期盘点属于后续资产管理范围。
- **维修保养**：支持常规保养、故障维修和事故维修，经办人、保养维修日期、当前里程、项目清单、发票与附件。总费用由项目清单汇总，提醒可按三个月或一万公里推算；维修厂选项限定供应商的维修厂分组。

维修类型通过 `sys_dictionary.type_id` 关联类型编码 `vehicleMaintenanceType` 加载；字典项自身的 `code` 可以不同。当前启用项已包含 `routine`、`repair`、`accident`，新增表单默认 `repair`（故障维修），`maintenance` 仅保留历史展示。2026-10-30 按实际关联查询及 `authenticated` 角色读取断言通过，无需补项，未修改数据库；核验结果见主仓忽略目录 `.artifacts/vms-maintenance-type-read-check-20261030.json`。

## 常见问题

| 问题               | 检查                                     |
| ------------------ | ---------------------------------------- |
| 找不到司机或员工   | 跨模块 RPC 权限、在职/启用状态和租户范围 |
| 档案审核按钮不可用 | 记录状态、精确按钮权限和审核人角色       |
| 到期提醒没有消失   | 新记录有效期、提醒刷新任务与关联车辆     |
| 里程无法保存       | 是否小于历史读数、时间冲突或来源重复     |
| 车辆健康建议不完整 | 保险、年检、维修、里程和事故数据是否齐全 |
