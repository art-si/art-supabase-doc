# TMS 司机端

Art Supabase TMS 司机端是与 Web 管理端共享同一条运单履约链路的 H5 / 微信小程序。司机只看到服务端授权给本人的任务，在移动端提交的定位、里程、照片、磅单、签收、回单和费用会同步回 TMS、FMS 与审批中心。

![TMS 司机工作台](/screenshots/tms-driver-home.png)

## 登录与首次使用

- H5 支持司机账号与密码登录。
- 微信小程序可以按部署配置启用手机号授权登录。
- 登录成功后先确认司机姓名、绑定车辆和当前任务是否正确。
- 未绑定司机档案或车辆时，应联系管理员修复账号、司机、租户和运单分配关系，不要借用他人账号。

## 标准履约流程

```text
接受任务
  → 到达装货地并定位打卡
  → 填写重量、上传现场照片与磅单
  → 记录发车时间、出车里程与车辆照片
  → 到达卸货地并定位打卡
  → 填写卸货资料
  → 记录签收人、回单与签字凭证
  → 记录收车时间、回场里程与车辆照片
  → 完成运单
```

### 接单与取消

在任务详情确认运单号、起讫地、计划时间、货物、联系人和车辆后接受任务。取消任务必须填写真实原因；服务端会重新校验当前状态，已经进入关键执行节点的运单不能随意取消。

### 装卸货定位打卡

到达现场后先授权定位并打卡。启用电子围栏时，位置不在允许范围内会阻止普通手动打卡；定位精度不足时应移动到开阔区域重试。打卡完成后录入毛重、皮重、净重，上传现场照片和磅单。

磅单 OCR 只生成辅助识别结果。司机必须核对数字和单位，识别失败时可以手工填写，最终提交值以司机确认内容为准。

### 发车、签收与收车

发车记录包含实际发车时间、出车里程和车辆照片。卸货完成后填写签收人和签收时间，上传完整回单与必要的签字照片。签收不等于运输完成，还需要记录收车时间、回场里程和车辆照片，系统据此补齐车辆里程台账。

### 费用上报

途中产生过路、停车、装卸或其他垫付费用时，从运单进入费用上报：选择费用项目、填写金额和发生日期、上传票据，可选定位与说明。OCR 结果应用前可以核对；提交后由 Web 管理端和审批中心处理，司机端可查看审核与结算状态。

## 现场操作建议

- 照片应清晰包含车牌、货物、现场或仪表盘等必要证据。
- 磅单、回单和票据应完整入镜，避免反光、裁切、遮挡和重复上传。
- 时间和里程支持按实际情况补录，但必须真实，系统会保留业务记录。
- 网络不稳定时先确认提交结果再重试，避免重复生成记录。

## 管理员部署提示

- H5 使用 `pnpm build:h5` 构建到 `docs/`；微信小程序使用 `pnpm build:mp-weixin`。
- 只向前端提供 Supabase publishable / `anon` key，禁止暴露 `service_role` 和 AI Provider 密钥。
- 微信小程序需要配置 AppID、合法域名、定位/相机/相册权限与手机号授权。
- 地图能力需要配置高德 Key、安全码和允许域名；业务写入仍以服务端身份、租户、分配关系和状态校验为准。

## 常见问题

| 问题           | 检查                                                 |
| -------------- | ---------------------------------------------------- |
| 登录后没有任务 | 司机档案、Auth 用户、租户、运单分配和运单状态        |
| 定位打卡失败   | 系统定位权限、网络、定位精度、电子围栏配置和现场距离 |
| 无法上传图片   | 相机/相册权限、文件大小、Storage 策略和网络          |
| 无法签收或完成 | 前置装卸货节点、必填凭证、运单状态和服务端校验       |
| 费用无法提交   | 运单状态、费用项目、金额、凭证与审批配置             |
