# MES 制造执行

MES 面向生产计划、现场执行、质量控制和全过程追溯，目标是以生产订单为主线，把排程、派工、投料、报工、检验、完工和批次/序列号串成可执行、可反馈的制造闭环。

::: tip 当前实施状态
MES 已接入生产工单、排程、现场任务、生产报工、报工审核与制造执行工作台。已下达工单可发起 WMS 领料申请；已审核完工实绩可进入 WMS 生产入库。跨系统全程追溯和部分现场采集仍需完善。
:::

## 目标生产流程

```text
生产需求 / 生产订单
  → 工艺版本与资源校验
  → 有限能力排程
  → 工序任务与派工
  → 开工、投料、报工和设备事件
  → 过程检验与异常处置
  → 完工与成品入库
  → 批次 / 序列号生产履历
```

## 上线前准备

1. 在 [MDM](/modules/mdm) 建立生产部门、生产人员、工厂日历、作业模板、工作中心和工艺路线。
2. 明确产品、物料、设备、人员和仓库的权威身份以及跨模块读取契约。
3. 定义生产订单、工序任务、派工、报工、检验和完工的状态机及反向操作规则。
4. 为查看、下达、派工、开工、报工、质检、完工、撤销和导出分别配置按钮权限。
5. 用测试租户跑通一条生产工单，核对数量、时间、人员、设备、报工审核和 WMS 库存联动。

## 与 MDM、WMS 协作

- MDM 负责稳定的生产组织、人员、日历、工作中心、作业模板与工艺路线；MES 在生产任务中保存执行时使用的版本或必要快照。
- [WMS](/modules/wms) 负责物料库存、领料/退料、配送和成品入库；MES 不直接修改库存余额。
- [PMIS](/modules/pmis) 管理设备点检、巡检和维护任务；MES 保留生产执行事实，设备任务状态不能代替报工或质检结果。
- 设备与人员身份来自权威来源，MES 只保存执行关联和发生时事实，不复制完整敏感档案。
- 跨模块数据通过租户隔离、字段最小化的 API/RPC 契约读取，业务仓之间不直接导入源码。

## 计划、派工与报工原则

- 排程必须基于明确的工艺版本、资源日历、工作中心和产能约束。
- 派工记录需要保留下达人、时间、目标人员/设备和任务版本。
- 报工要区分良品、不良、返工、报废、工时和物料批次，并防止重复提交。
- 状态回退、数量冲销和补录必须使用受控反向流程，不能直接覆盖历史事件。

## 质量与追溯原则

过程检验、缺陷、处置、返工和放行需要关联同一生产任务及批次/序列号。追溯链应能从成品反查原料批次、工艺版本、工作中心、设备、人员、时间和质量结果，也能从原料正向定位受影响成品。

## 权限与安全

- 普通用户只能读取当前租户及授权生产范围内的数据。
- 派工、开工、报工、质检判定、完工和撤销必须在 UI 与服务端使用独立权限。
- 页面可见不代表后端授权，数据库 RLS、RPC 和领域状态机是最终边界。
- 尚未接通的现场采集与追溯环节不得用前端模拟写入或直接改表替代。

## 常见问题

| 问题                    | 检查                                                 |
| ----------------------- | ---------------------------------------------------- |
| 只能看到制造工作台      | 核对 MES 菜单与工单、排程、报工等页面授权            |
| 找不到工作中心或工艺    | MDM 配置状态、租户、版本生效时间和跨模块读取契约     |
| 生产任务无法下达        | 订单状态、工艺版本、资源日历、物料与按钮权限         |
| 报工数量或时间异常      | 重复提交、工序状态、单位换算、班次跨午夜和服务端幂等 |
| 完工后 WMS 没有入库任务 | 完工状态、接口事件、物料批次和 WMS 契约              |
