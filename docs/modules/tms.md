# TMS 智慧运输

TMS 覆盖运输主数据、开单、运单执行、配载、在途监控、签收回单和结算协作。推荐先建立可靠主数据，再进入订单与运单流程。

## 上线前准备

1. 维护客户、客户地址和常用线路。
2. 维护承运商、司机、车辆引用和站点。
3. 建立货物、合同、客户价格与承运商价格。
4. 为开单、配载、发车、签收、费用和 AI 分析分别配置按钮权限。
5. 需要地图时配置高德地图浏览器 Key、安全码和允许域名。

## 标准业务流程

```text
客户委托
  → 开单 / AI 识别
  → 生成原始运输单
  → 待运载：正向货配载 / 合单 / 拆单
  → 生成调度执行运单并分配车辆、司机
  → 已配载 / 发车
  → 在途监控与异常处置
  → 到达、签收、回单
  → 费用、对账、收付款与利润
```

## 智能开单

在“开单”页面选择客户、起讫地、货物、时间和运输要求。已有合同与价格时优先引用主数据，避免在订单中重复录入不可治理的文本。客户未明确选择“允许合单”时，原始单默认禁止合单。

AI 智能填单可以识别文本或图片，并按当前租户匹配站点、客户、地址及货物档案。缺失的档案会列入前置资料清单；具备对应 `TmsStation:Add`、`TmsCustomer:Add`、`TmsCustomerAddress:Add` 或 `TmsCargo:Add` 权限的用户，可勾选资料完整的项目一键建档。客户和默认地址同时创建时需要两项新增权限。建档须人工确认，创建后会重新匹配；订单仍需核对并单独保存。保存前确认：

- 客户与地址是否匹配当前租户。
- 收发货联系人、电话和时间是否准确。
- 重量、体积、件数及单位是否一致。
- 是否需要拆分多个运单。
- 客户价格、承运商价格和附加费用是否符合合同。

## 运单与配载

“待运载运单”列出仍有未调度货量的原始运输单；“已配载运单”列出调度生成的执行运单。每张执行运单都有独立运单号，来源明细保存在 `tms_waybill_order_allocation`。原始运输单的客户、货物和收发要求在首次调度后保持不变，详情可反查全部执行运单。

- 正向货配载：一张原始单生成一张执行运单。
- 合单：客户逐单明确允许、线路与时间窗口匹配、货物兼容且收货地址相近时，多张原始单生成一张执行运单，共用一车一号；各原始单保留独立货量、费用和签收记录。合单执行运单不能再次拆分。
- 拆单：按件数、重量、体积或货物行分配，首次至少生成两张执行运单；每批可安排不同车辆、时间和收货地址。未分配货量仍留在待运载列表，原始单显示部分调度，可继续添加单个或多个批次。所有有效执行运单的分配量不能超过原始货物行总量。

服务端会再次检查按钮权限、租户、车辆与司机资质、核载吨位和容积、货物余额，以及合单许可与兼容条件。运费按原始单货物行重量分摊；总重量为零时依次按体积、件数分摊。末批吸收分位舍入差额，确保各执行批次分摊金额合计等于原始单运费。

### 同一趟运输的返程配货

返程配货作为主运输任务下的返程子单保存，正向货和返程货共用主任务号、车辆与司机。返程分别登记运费收入、信息费、技术服务费及独立路桥杂费；共用成本可归集主单或按比例分摊。列表和详情区分业务预计收入、费用、毛利与财务审核后的实际值，避免重复计入成本。未完成正向派车配载的主单不能作为返程候选。

中转站支持多选并保留途经顺序。司机提成按车型、线路、货运方向、重量/方量和生效日期匹配规则，任务保存时保留预计算快照；后续规则变更不会静默重写历史任务快照。

运单详情的“核对司机提成”按正向货、返程配货分别展示预估与调整记录。每次保存只修改当前货段，原因、操作人和时间绑定该货段留痕；重复人工调整仍保留最初计算依据。货段切换保留当前窗口的草稿，关闭后丢弃未保存内容。保存期间禁止重复提交和普通关闭，路由强制关闭后的旧请求也不能覆盖新窗口。

## 司机资料与公司认证

司机资料按基本信息、身份证、驾驶证、从业资格证、其他信息、财务信息、司机证件和提成配置分区维护。提成关联车型与车辆、挂车共用分类插画和规格参选组件，可核对车长、容积与载重；选定车牌后带入并锁定车型，取消参选保留原值。自营司机与其他归属司机的接单资质规则分别校验；承运商司机必须关联同租户承运商。证件图片、识别结果与人工修改仍需按权限核对和保存。

公司认证分为企业资质信息、授权委托书、开户认证、道路运输经营许可证和企业电子签五个页签，变更保留独立申请及内部审核记录。内部审核状态不等于钱包开通或第三方签章成功。真实钱包、电子签、短信/人脸认证和微信扫码注册资料回填需要服务商接口，线上支付确认书需要正式模板；当前用户尚未提供这些接入条件。

AI 异常研判用于汇总信号和提出处置建议，真正的工单、通知、改派或状态变化仍由有权限的操作人员确认。

## 签收与回单

到达后按执行运单登记签收时间、签收人和回单附件，并逐张原始单记录实收件数、异常件数及说明。合单的破损只归属对应原始单；拆单的原始单在各批次全部签收前保持部分签收。需要更正时可复核签收，系统追加审计事件。OCR 可以辅助识别回单，但需人工复核单号、签字、日期和异常说明。

客户对账以原始运输单为单位，一张原始单只计一次原始运费；同车合单的不同客户仍各有独立对账项。只有原始单全部签收后才进入客户对账候选。承运商对账按调度执行运单归集已审核的运单成本，执行单分摊运费在待对账费用选择时作为只读对照；它不会自动变成承运商应付，以免把客户应收和承运成本混为一笔。

## 运单费用明细

执行运单详情的“费用明细”同时展示执行运费、关联订单收费与收款分配，以及该执行运单在司机端上报和 Web 端录入的全部费用单。合单、拆单以执行单分摊运费为准，原始订单的其他收费项目仍在对应订单详情查看。费用单显示来源、金额、审核与结算状态、发生时间、数量和单价、服务商、收款信息、地点、报销与付款单号、说明和票据；字段权限为隐藏或脱敏时按权限展示，任一费用金额不可读时不显示申报合计。

费用读取沿用 `tms_get_waybill_detail_secure`：先检查运单详情菜单权限和当前租户读取范围，再按 `tms.waybill_cost` 字段权限过滤费用明细。司机端与 Web 端共用 `tms_waybill_cost`，按 `source_type` 区分来源；费用明细仅供查看，不产生业务数据写入。

## 客户、常用地址与货物主数据

客户资料与货物资料左侧使用可调整宽度的分组面板，选择父分组会连同下级筛选右侧列表；表单可从同一分组树选组。常用地址支持粘贴或语音识别联系人、电话、收发货方与省市区地址，识别结果只回填表单，保存前由用户核对；地址简称和营业时间与地址一同保存。货物身份关联 MDM 物料编码，名称、规格与唯一基本单位由物料主数据派生，运输尺寸、重量等参数仍在 TMS 维护；复制货物参数时需重新选择物料编码。

## 司机端协同

独立的 [TMS 司机端](/modules/driver) 支持 H5 与微信小程序。调度将运单分配给司机后，司机可在移动端接受任务，完成装卸货定位打卡、发车、到达、签收、收车、现场凭证和费用上报。

Web 管理端与司机端共享同一条服务端运单状态机。若两端显示不一致，先检查司机分配、状态同步、服务端事件和当前会话，不要通过直接修改数据库状态绕过业务节点。

## 价格与结算

客户价格与承运商价格应分别维护，并保留适用线路、货物、计价单位和生效时间。历史交易需要快照的价格或名称可以保留快照字段；普通主数据名称不要重复拷贝到业务表。
